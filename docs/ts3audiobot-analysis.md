## 一、TS3AudioBot 项目概览

TS3AudioBot 是一个开源的 TeamSpeak 3/5 音乐机器人，采用 **C# (.NET Core 3.1) 后端 + Vue 2 + TypeScript 前端**技术栈。其核心特点包括：

- 多实例 Bot 管理（同时运行多个机器人）
- 支持 YouTube、SoundCloud、Twitch、Bandcamp、本地媒体
- 命令系统完全映射为 REST API
- 自动生成 OpenAPI 3.0 文档
- TOML 权限系统 + C# 运行时插件编译
- 自研 headless TS3 客户端库（TSLib）

## 二、可直接学习采用的功能（按价值/难度排序）

### 1. 生成式播放列表封面（高价值 / 低难度）

TS3AudioBot 为每个播放列表生成一张独特的 5x5 像素艺术封面图，算法基于播放列表名称的哈希值，通过三角函数生成颜色矩阵。无需存储图片文件，纯计算生成。

**当前项目现状：** 播放列表和收藏页面使用固定图标或歌曲封面，缺乏视觉辨识度。

**采用价值：** 零存储成本、零网络请求，给播放列表赋予独特视觉身份，提升 UI 质感。

**实现思路：** 在 `web/src/utils/` 中添加一个 `genPlaylistCover(name: string)` 函数，用 Canvas 或 CSS `box-shadow` 像素画技术生成彩色方块矩阵。

---

### 2. TS3 服务器树可视化（高价值 / 中等难度）

TS3AudioBot 在网页端渲染了完整的 TS3 服务器频道树，包括：
- 频道层级结构（支持 `cspacer`、`rspacer` 等特殊频道类型）
- 在线用户列表
- 当前 bot 所在位置的"播放中"波浪动画指示器
- 右键菜单：加入频道、Whisper 到频道/用户

**当前项目现状：** 前端完全没有 TS 服务器状态展示，用户不知道 bot 在哪个频道、频道里有多少人。

**采用价值：** 让用户直观看到 bot 的连接状态和位置，提升控制感。

**实现思路：** 后端新增 `/api/bot/:id/server-tree` 接口，返回频道树结构；前端新增 `ServerTree.vue` 递归组件渲染树形 UI。

---

### 3. 设置难度分级 + 实时搜索过滤（高价值 / 低难度）

TS3AudioBot 的 Bot 配置编辑器将所有设置项标记为 `Simple / Advanced / Expert` 三个难度等级，用户可以按等级过滤，也可以按关键词搜索。配置变更实时自动保存（带 debounce）。

**当前项目现状：** Settings 页面使用简单的表单，所有配置项平铺展示，没有分级或搜索。

**采用价值：** 降低新用户配置门槛，减少"看到一堆设置就头大"的情况。

**实现思路：** 在 `config.ts` 的 `BotConfig` 或前端配置表单中增加 `level` 元数据，配合 `Tabs` + `SearchInput` 实现过滤。

---

### 4. 内联可编辑文本（中等价值 / 极低难度）

TS3AudioBot 大量使用"点击即编辑"的文本组件：鼠标悬停显示编辑图标，点击后变成输入框，Enter 保存、Esc 取消、失去焦点取消。

**当前项目现状：** 所有需要编辑的字段都是跳转页面或弹窗表单，操作路径较长。

**采用价值：** 提升高频操作（如重命名 bot、修改播放列表名称）的效率。

**实现思路：** 封装 `EditableText.vue` 组件，使用 `v-if` 切换文本/输入框模式。

---

### 5. 播放列表拖拽排序 + 外部链接拖放（高价值 / 低难度）

TS3AudioBot 的播放列表编辑器支持：
- 原生 HTML5 drag-and-drop 重新排序歌曲
- 从其他浏览器标签直接拖放 URL 到播放列表中
- 分页显示（每页 20 首）

**当前项目现状：** Queue 组件使用了 `vuedraggable` 支持拖拽，但播放列表管理功能较弱，不支持外部拖放。

**采用价值：** 播放列表是核心功能，增强编辑体验能显著提升用户满意度。

**实现思路：** 在 `Playlist.vue` 或 `Queue.vue` 中增加 `@drop` 事件监听，解析拖放的 URL 文本。

---

### 6. 实时系统状态图表（中等价值 / 中等难度）

TS3AudioBot 的 Overview 页面展示了自定义 SVG 实现的 CPU 和内存实时曲线图，每秒更新，Y 轴自动缩放，支持 B/KB/MB/GB 单位自动转换。没有引入任何图表库，纯 SVG + 数学计算。

**当前项目现状：** 完全没有系统监控页面。

**采用价值：** 对于自托管用户，能快速判断服务器资源是否充足。

**实现思路：** 后端新增 `/api/system/stats` 接口（使用 Node.js `os` 模块），前端用 SVG path 绘制折线图。

---

### 7. OpenAPI / Swagger 自动文档（中等价值 / 低难度）

TS3AudioBot 通过 C# 反射自动生成 OpenAPI 3.0 规范，内嵌 Swagger UI 到 `/openapi` 页面。API 参数、返回类型、响应码全部自动推导。

**当前项目现状：** API 没有文档，新开发者需要阅读源码了解接口。

**采用价值：** 降低二次开发门槛，方便前端/移动端开发者对接。

**实现思路：** 引入 `swagger-ui-express` + `openapi-types`，手写 `openapi.yaml` 或用小工具从路由代码生成。

## 三、可添加但需评估的新功能

### 1. Quiz 模式（猜歌游戏）

TS3AudioBot 支持一种趣味模式：歌曲标题对非点歌者隐藏，其他用户需要猜歌名。这本质上是一个社交游戏功能。

**评估：** 适合小团体娱乐场景，实现难度不高（前端隐藏歌曲名 + 后端增加模式状态），但使用频率可能较低。可作为"彩蛋功能"后续考虑。

---

### 2. Whisper 语音目标切换

TS3AudioBot 允许 bot 在"频道广播"和"Whisper 到指定用户/频道"之间切换，网页端可以直接点击服务器树中的用户/频道来切换音频目标。

**评估：** 对于大型 TS 服务器很有用（不想让音乐打扰全频道），但当前项目主要面向小团体，优先级不高。

---

### 3. 多 Bot 实例管理增强

TS3AudioBot 的前端围绕"多实例"设计：Bot 列表页、每个 Bot 的独立 Dashboard、独立配置、独立播放控制。

**评估：** 当前项目后端已经支持多 bot（`BotManager`），但前端主要是单 bot 视角。如果要正式支持多 bot，需要新增 Bot 列表页、切换 bot 的导航栏、每个 bot 的独立状态缓存。工作量较大，建议等有明确多用户需求时再实施。

## 四、当前项目的相对优势

对比 TS3AudioBot，当前项目也有不少对方没有的优势，移植时无需丢弃：

| 优势 | 说明 |
|------|------|
| **现代化前端栈** | Vue 3 + Composition API + Pinia + Tailwind CSS v4，相比 Vue 2 + Options API + Buefy 更现代 |
| **多平台中文音乐源** | 网易云、QQ音乐、Bilibili 是 TS3AudioBot 不具备的，对中文用户价值极高 |
| **歌词同步显示** | TS3AudioBot 没有歌词功能，当前项目的逐字/逐行歌词同步是核心竞争力 |
| **HTTP-only Cookie 认证** | 比 TS3AudioBot 的 Basic Auth + localStorage 更安全（防 XSS） |
| **收藏与历史系统** | TS3AudioBot 的历史页是 WIP 占位符，当前项目的收藏+搜索已完全可用 |
| **WebSocket 状态同步** | 多端实时同步播放状态、队列、收藏变更 |

## 五、实施优先级建议

1. **内联可编辑文本** - 组件封装简单，可立即提升多处交互

3. **设置难度分级** - 在前端增加过滤逻辑即可

### 中期（1 周内）

5. **OpenAPI 文档** - 引入 swagger-ui-express，手写 yaml
6. **TS3 服务器树可视化** - 需要前后端配合，但 API 数据量不大

### 长期（按需）
7. **实时系统图表** - 需要新增系统监控 API
8. **Quiz 模式** - 趣味功能，等有明确需求再实施

## 六、结论

TS3AudioBot 作为成熟项目，在**系统可视化**（服务器树、资源图表）、**配置 UX**（难度分级、内联编辑）、**播放列表体验**（像素封面、拖拽排序）方面有很多值得借鉴的设计。当前项目在技术栈现代化和中文音乐生态上有明显优势，两者互补性强。

建议优先采用**低投入高回报**的功能（生成式封面、内联编辑、设置分级），这些能在不改动核心架构的情况下显著提升用户体验。
