## 一、分叉现状

| 项目 | 状态 |
|------|------|
| 分叉点 | `64ecd92`（2026-04-29，PR #43 fm-artist-playlist） |
| 上游新增提交 | **379 个**，最新 `af1dac8`（2026-08-14） |
| 上游版本线 | v1.8.x → v1.9.0 → **v2.0.0**（2026-05-27，WebUI 鉴权重构大版本）→ v1.10.0 ~ v1.13.0 |
| 本地自有提交 | 14 个（前端 Tailwind 重设计、自研 JWT 鉴权、频道树、移动端、Docker 发布流等） |

两个**结构性分叉**决定了后续无法直接 `git merge upstream/main`，一切跟进只能按功能 cherry-pick 或重写：

1. **前端样式体系不同**：我们已迁移到 Tailwind CSS 4 + Vite 6 + 基础组件库；上游仍是 SCSS + Vite 5。`web/` 目录几乎必然大面积冲突。
2. **鉴权体系不同**：我们用 config.json 双密码 + JWT Cookie；上游 v2.0.0 用 SQLite 多用户 + bcrypt 会话 + 细粒度权限 + 游客模式。同名需求、两套实现，跟进意味着"替换"而非"合并"。

### 2.2 鉴权体系（v2.0.0）——与我们方案的根本分歧

| 维度 | 上游 v2.0.0 | 我们 fork |
|------|-------------|-----------|
| 账号存储 | SQLite `users` / `sessions` / `user_audit` 三表，多用户，bcrypt | config.json 两个密码（adminPassword / userPassword） |
| 会话 | 服务端会话表 + HttpOnly Cookie，7 天滚动续期，同账号最多 10 并发会话 | JWT（`jwtExpiresIn` 默认 7d）+ HttpOnly Cookie |
| 角色与权限 | admin / member + 每成员 5 项细粒度能力（播放控制/队列/机器人管理/平台登录/音质）+ 按机器人授权白名单 | admin / user 两级，无细粒度 |
| 游客模式 | 有：免登录进入 WebUI，8 个权限开关 + 机器人作用域白名单，默认关闭 | 无 |
| 安全防护 | CSRF Origin 校验、登录限流（每 IP 5 次/分）、`X-Frame-Options`/CSP、noindex | 登录限流 |
| 首次引导 | `/first-run` 创建首位管理员（用户名 3-32 字符 + 密码 ≥8 位） | `/setup` 设置两套密码 |
| 密码找回 | FAQ 给出 SQLite 重置流程（清空 users/sessions 或 bcrypt 替换哈希） | README 未覆盖 |

评价：上游这套明显更完整（多用户、细粒度授权、游客、审计、会话管理）。若跟进是大型重构，会牵动后端 auth 模块和整个前端登录流。

### 2.3 队列与设置持久化（v1.11.0，#119/#125）

- **保存/加载播放清单**：`!save <名称>` / `!load [-a] <名称>` / `!queues` + WebUI「已存队列」页；网页保存可选私有/共享，聊天保存进共享清单；上限每所有者 50 份 × 1000 首；由 `savedQueuesEnabled` 门控（默认关）。
- **重启自动恢复队列并续播**：同开关门控；只能从当前曲目开头恢复（不记忆进度）；Spotify 恢复为尽力而为。
- **`playKeepsQueue`**：单曲直接播放不清空队列、播完继续原队列（独立开关，默认关）。
- **设置持久化（#125）**：音量/播放模式按机器人落库（`bot_instances.volume` / `play_mode`），各平台音质落 `config.json` 的 `audioQuality`；聊天命令、WebUI、REST 三个入口的改动均落盘。

> 注意：上游的「本地收藏歌单」（`favorite_playlists`，按用户收藏**歌单**）与我们的「收藏夹」（`favorites` 表，收藏**歌曲**、跨客户端同步）是两个不同功能，名字相近，文档对比时不要混淆。

### 2.4 本地媒体上传（v1.9.0 音频 / v1.13.0 视频 #149/#151）

- 搜索页拖拽/选择上传；音频 mp3/flac/wav/m4a/ogg/opus 等，视频 mp4/mov/avi/mkv/flv/wmv 等。
- 视频**无损 remux 只留音轨**（不重编码，720p 素材实测落盘为原文件 14%），无音轨的视频在上传时即拒绝；单文件上限 500MB。
- 设置 → 行为设置 可开关；播放结束或停止/清空/替换队列时自动清理服务端文件。
- 上游明确**不做**"读取服务器任意路径文件"（等于开放任意文件读取），服务器媒体库场景交给 Jellyfin。

### 2.5 聊天命令增强

- **`!search <歌名> [平台标志]` + `!play #<序号>` + `!play id <id>` + 直接粘贴歌曲链接**：解决"同名歌曲只能播到最热门那首"（FAQ 有专门条目）。旧写法 `!play id:<id>` 兼容（#139/#145）。
- 新平台标志：`-n`（网易云显式）、`-k`（酷狗）、`-j`（Jellyfin）。
- **随机模式下 `!pn` 真正下一首播放**（#141/#144），顺带修了插删歌曲后待播位置漂移、删多了静默停止两个问题。
- `!lyrics` 发送完整歌词并按 UTF-8 字节安全分片（#116，之前截断前 10 行且长消息触及 TS 单条 ~1KB 上限）。
- **语音闪避 voice ducking**（v1.11.2 #136/#137）：频道内有人说话时平滑压低音乐、停止后平滑恢复；默认关，可调保留音量比例。

### 2.6 部署与运维（上游 README 信息量最大的增量）

- **config.json 移到 `data/config.json`**（#86）：旧版写在项目根目录、不在 Docker 挂载卷内导致重启丢失；升级自动迁移。
- **`trustProxy` + 反向代理注意事项**：Cookie Secure 标志、登录限流按真实 IP 分桶、审计日志 IP，三项都依赖它；直接暴露端口无需开启。
- **Node 版本策略 + ABI 自愈安装脚本**（v1.12.0 #140/#147）：推荐 20/22 LTS（真实下限 20.19+/22.12+）；setup 脚本子进程真实加载每个原生模块校验 ABI，不匹配自动重装、失败原子还原；`start` 前预检并明确报出"哪个模块、两个 ABI 各是多少"；三模块串行处理修了"源码编译阻塞事件循环导致 80MB ffmpeg 下载被误判超时后静默丢失"。
- **QQ 音乐 API 版本锁定 `~2.4.0`**（需 Node ≥ 20.17）：明示 2.3.0/2.3.1 是纯 ESM、必报 `ERR_REQUIRE_ESM`，警告不要手动 `npm update`；#122 将内嵌 sidecar 强制绑定 `qqMusicApiPort`（默认 3200），修了"日志 baseURL 3200、实际监听 3300 导致二维码不弹"。
- **WebUI 防收录**（#128）：`X-Robots-Tag: noindex` + `/robots.txt` + meta 标签；明示这只是防索引不是访问控制。
- **`adminGroups` 正式启用**：6 个管理类聊天命令（stop/clear/remove/move/vol/mode）可限指定 TS 服务器组；为空不限制（向后兼容）；设置页可视化配置；fail-closed。
- **忘记管理员密码 FAQ**：`sqlite3` 清空 users/sessions 重进 first-run，或 bcrypt 哈希替换。
- 部署公网防暴力 FAQ：内置 `/login` 限流 5 次/分/IP，建议反代层再加一层。

### 2.7 值得核对我们是否同样存在的修复

- **v1.11.1（#135）丢弃自回显消息**：TeamSpeak 会把机器人自己发的频道消息回推给它，`!help` 超长分段后第二段以 `!artist` 开头被自己当命令执行——机器人自己点歌。**已核对我们分叉的代码：`src/bot/instance.ts` 的 `handleTextMessage` 没有任何"发送者是机器人自身"的过滤，该 bug 大概率同样存在。**
- **#148 连接前不发注定失败的头像上传**：机器人构造阶段读出已保存头像就立刻发起文件传输，但那时 TS 还没连上。我们有同类 profile 头像逻辑，值得核对。
- **#89 B站长音频约 16 分钟被暂停**：ffmpeg 加 `-reconnect_at_eof`（B站 CDN 在 token 到期时提前断连造成 EOF）+ "远离结尾的卡死看门狗"自动推进下一首。
- **#84 音量曲线**：0-100 改为 `0.2x + 0.8x^8` 连续单调曲线，消除 80-99 死区与 100 处突跳。
- **移动端补课**（v1.12.0 #142/#143/#138）：进度条可拖、单击歌曲行即播、**站点图标 + Web App Manifest（PWA）**、QQ 扫码提示改"手机QQ"。我们已有自己的移动端体系（底部抽屉/节流），无需跟随，但站点图标/PWA 我们 README 未提、值得检查是否已有。

2. **更新日志组织方式**：上游按版本号分节（v1.13.0 / v1.12.0 / …），每条带 issue/PR 链接与贡献者，并显式标注"没有配置变化，升级无需任何操作"。比我们现在"最新版本一大段无版本号"更可维护。
3. **"重启后保留的播放设置"行为说明表**：哪些设置持久化、存在哪里、哪些不保留——用户非常需要而我们完全没有。
4. **配置文件节写法**：逐字段说明用途与现状（如 `adminPassword` 废弃、`adminGroups` 启用）、位置变更迁移说明。

## 五、行动建议（按优先级）

### P0 — 立即处理

1. **`@sansenjian/qq-music-api` 版本风险（具体发现）**：我们 package.json 是 `^2.2.10`，该范围覆盖 2.3.x——上游明示 2.3.0/2.3.1 为纯 ESM、启动必报 `ERR_REQUIRE_ESM`。全新环境 `npm install` 可能拉到坏版本。建议锁到精确 `2.2.x`，或跟随上游升 `~2.4.0`（要求 Node ≥ 20.17）。
